A Housing Model for 3D Printing

When inexpensive housings can be bought, there's no point printing them on a 3D printer, especially since the housing's small details require a high-resolution printer, and such printing takes time and is not cheap.
For 3D printing, you can download the STL file of the 3D housing model.
The housing parts can be held together by four strips of 0.5mm-thick fiberglass laminate - this seemed to me more reliable for repeated assembly/disassembly of the housing than plastic standoffs.
The strips fit snugly into slots in the vertical walls.
For the strips to be usable, the print resolution needs to be high, or the strip thickness will need to be adjusted after printing to account for 3D-printing inaccuracy.
High-quality, expensive 3D printing with a 0.025mm resolution will produce a slot width after printing of 0.500±0.050mm.
It's simpler and cheaper to use glue that will allow the housing parts to be separated again if needed. 
Here you can see the adapter housing in a 3D animation
A cable up to 3.5mm in diameter can be routed into this housing. If needed, the user can enlarge the cutout in the wall to install a shock-absorbing cable gland. For this, notches sized for a commercial cable gland are provided in the wall.

"Housings" Made from Heat-Shrink Tubing

For personal use, a housing made from ordinary heat-shrink tubing with a 2:1 shrink ratio and an initial diameter of 12mm is quite sufficient.
In the adapter shown in the photo, the cable entry is made from several heat-shrink tubes. 
The first tube is the shortest; after it shrinks, a longer tube is put over it.
The tubes are aligned with the edge of the adapter board. Each next tube is longer than the previous one, which provides
  • smooth transitions, since each next, longer tube covers the cut edges of all the previous tubes,
  • and a gradual decrease in the cable entry's stiffness with distance from the adapter.
This cable entry is better than a commercial one, since a commercial one may be either insufficiently stiff compared to the cable, or substantially stiffer than the cable, in which case the cable would bend/break where it exits the cable entry.

 If a stronger housing is needed, an adhesive-lined heat-shrink tube with a 3:1 shrink ratio or 4:1 and an initial diameter of 12mm will work.
The board is first placed into ordinary 2:1 heat-shrink - it's enough to cover just the board, without covering the USB connector, and on the  
cable side, trim the heat-shrink at the edge of the board. This heat-shrink protects the components on the board from the adhesive of the 3:1 heat-shrink, whose effect is unknown.
The adhesive-lined 3:1 heat-shrink should partially cover the USB connector and be trimmed on the cable-entry side with a few millimeters to spare.
After cooling, the 3:1 heat-shrink becomes quite strong and thick (about 1mm).

The UPDI Programmer and an ATmega808-Based Adapter

(a megaAVR 0-series microcontroller)

For megaAVR 0-series microcontrollers, it's hard to find a cheap programmer with control software that's convenient to use - expensive universal programmers are offered, for both AVR and PIC microcontrollers, supporting the set of programming interfaces for all series of these microcontrollers.
On GitHub you can find source code for applications that work with the programmer. These programs are run from the command line and require entering a number of parameters.
Recommendations for building a programmer from a USB<>UART adapter with a small modification can also be found.

Unfortunately, there are still few program examples online for the megaAVR 0-series microcontrollers, and the register organization and naming, as well as controlling the microcontroller's peripherals, have changed significantly and require study.

The photo shows a homemade UPDI programmer - or rather, it's a USB UART adapter with additional components that let it work as a UPDI programmer.
It can also work as a USB UART adapter, for example for programming the ESP8266 and ESP32 Wi-Fi modules, as well as microcontrollers directly from the Arduino IDE.

In  the photo, the UPDI programmer is connected to the computer's USB port
and to the ATmega808 microcontroller being programmed on the adapter board.

The +3.3V supply voltage is fed to the adapter from the programmer.
You can watch the full UPDI programming video on YouTube

An application runs on the computer that loads the program into the microcontroller,
In this case, it's a 256-byte Bootloader program for the ATmega808 microcontroller.

the GIF image demonstrates
- reading the state of fuse byte 8,
- writing "1" into it (1 * 256 bytes - one boot sector)
- selecting the hex file with the firmware (Bootloader.hex)
- writing 4 pages of 64 bytes each (256 bytes total; 64 bytes is the ATmega808's memory page size)
- automatic USB device disconnection after loading
- connecting the device to USB by pressing the ENABLE button
- reading 4 pages of 64 bytes each to verify the firmware in the microcontroller.

Working programs will later be loaded by THIS SAME APPLICATION, via the Bootloader loaded into the microcontroller;
the UPDI programmer is then no longer needed - it is disconnected from the adapter and from USB,
and the adapter itself is connected to the computer's USB port,

Using I2C SPI 1-Wire USB Adapters

The I2C SPI 1-Wire USB Adapter and MEMS Accelerometers with an SPI Interface.

The board of the low-noise MEMS accelerometer with an SPI interface is connected to the I2C SPI 1-Wire adapter USB based on the ATmega8A microcontroller by a 7-meter, five-wire cable.

The accelerometer board is on a ruler, between the 8cm and 9cm marks. The accelerometer board's dimensions are 4x13mm, with a mounting hole.
The board is single-sided and can be attached to the object under test with glue - in this case, the section of the board with the mounting hole can be cut off, reducing the board's length to 9mm (dimensions 4x9mm).
The cable is made from MGTF 0.03 wire placed inside soft heat-shrink tubing.
Advantages compared to RS-485 accelerometers : the accelerometer board's minimal weight and the cable's flexibility ensure minimal mechanical impact on the object under test, to which the accelerometer is attached; the drawback - lower noise immunity: under strong electrical interference (machine tools, welding), the RS-485 interface will work more reliably.

For the operation of the MEMS accelerometer chip, c the I2C SPI adapter 1-Wire USB it is enough to use the computer application matching the chosen accelerometer,
and place the MEMS accelerometer chip, with one or two capacitors, on a separate board.
 
Using the adapter lets you quickly swap accelerometers, for example connecting boards with different accelerometers to measure weak and strong accelerations.
The weight and dimensions of a separate board with a sensor (an accelerometer or gyroscope) are much lower than the weight and size of a board on which, besides the sensor, a controller and a connector are also located.
With the adapter, you can use a separate small, lightweight sensor board. The cable can be made as light and flexible as possible.

A light, compact board, and a light, flexible cable make it possible to attach the sensor board over a minimal area and will have minimal mechanical impact on the object under test. This is especially important when measuring on objects of small mass, or, for example, on freely swinging objects - the lower the accelerometer's mass and the softer and lighter the cable, the less damping they introduce.

To the I2C SPI 1-Wire adapter USB MEMS accelerometers with an SPI interface can be connected, including those installed in:USB accelerometers   or in  the precision accelerometer;
for example, the popular ADXL345 accelerometer with a measurable-acceleration range of ±16g  (±2g / ±4g / ±8g / ±16g), a compatible ADXL375 accelerometer with a range of ±200g (±25g / ±50g / ±100g / ±200g) .
Each type of MEMS accelerometer requires its own software - both for the microcontroller and for the computer.
To increase the distance from the computer to the adapter, and therefore to the sensors, by another 1.8 meters a standard cable extension can additionally be used: a USB-A-plug < > USB-A-socket.

A GPS Module with a UART Interface and an The I2C SPI 1-Wire USB Adapter on a megaAVR 0-series Microcontroller.

A I2C SPI 1-Wire adapter USB GPS module is connected to an adapter based on the megaAVR 0-series microcontroller.
The microcontroller shown in the photo, the megaAVR 0-series in a 28-pin package, supports three hardware USART channels.
The microcontroller receives text information sent by the GPS module, extracts the necessary part from it, and converts it into digital data (coordinates, time, etc.) for further use,
for example, to steer a carp-fishing float boat's rudder.
 
One of the microcontroller's USART channels is used to communicate with the computer over USB.

Another USART channel is brought out to the microcontroller's pins, but if the device needs to use a low-frequency 32kHz or 32768Hz quartz resonator for operation, these same pins will be used to connect the quartz resonator.
On the underside of the board, contact pads are reserved for connecting either a quartz resonator or an external UART-interface device.
 
The third USART channel uses the same lines as one of the SPI interface channels, which was used for connecting the accelerometer (see the previous photo).
The GPS module is connected to this channel.
 
The choice of which microcontroller peripheral (here, USART or SPI) the pins are connected to is made in software - the microcontroller supports pin multiplexing.
