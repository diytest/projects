I2C SPI 1-Wire USB adapter

I2C SPI 1-Wire Adapters < > USB based on the STM8S003 and ATmega8A/ATmega328P microcontrollers, as well as the ATmega808 (a new megaAVR 0-series), provide a connection to a computer for various devices or chips with I2C, SPI and 1-Wire interfaces.
and for ATmega808 and with the interface UART.
The adapters can be used both as turnkey devices for your own systems and as developer kits (Starter Kits) for learning microcontrollers - both for programmers who want to quickly switch to a new microcontroller series and for those for whom the Arduino development environment is enough.
Learning the megaAVR 0-series microcontrollers (ATmega808/ATmega809, etc.) is especially relevant:
  • they have much broader capabilities than ATmega8/ATmega328P,
  • the ATmega808 is produced not only in a TQFP32 package, but also in TQFP48 and SSOP28 (used in the adapter),
  • and they are sold significantly cheaper.
However, programming them differs significantly from the ATmega8, and no ready-made, inexpensive programmers compatible with the Microchip Studio development environment are produced.

I regularly use such an adapter for testing all sorts of I2C, SPI, 1-Wire, or UART devices and for debugging software.
A proven adapter and software, well-debugged in terms of sending/receiving data over the I2C, SPI, and 1-Wire interfaces, greatly ease learning to work with new devices.
All that's left is to figure out from the documentation of the new device being connected which commands to send to which address, and from which registers to read the results.

 The I2C SPI 1-Wire Adapter<>USB - is a finished, compact device in a housing,

 which a user can employ as part of their own systems,
without spending time on making a board, choosing a housing, and developing software, 

which is achieved through
- the compatibility of the adapter boards with standard, inexpensive housings;
- the ability to have simultaneous connection of several devices with different interfaces to the adapter - I2C, SPI, and 1-Wire;
- the variety of software in the example library;
- the simplicity of programming the adapters based on the ATmega8/ATmega328P and ATmega808 microcontrollers - with the Bootloader already flashed, firmware for these microcontrollers is uploaded without a programmer, over USB;
- the ability to switch to programming mode and back to run mode by a command from the computer; when returning to run mode, the Bootloader computer application does not need to be closed - it can disconnect from the adapter automatically, and to return to loading via the Bootloader, you only need to press a button in that application;
- compatibility with the Arduino development environment (convenient for beginners: lots of examples).

That is,
to switch to programming mode, it is not necessary to short contacts on the adapter board before connecting it to USB, and returning to running the working program does not require disconnecting and reconnecting the adapter.
You can switch between applications without restarting the Bootloader application before each programming session.
With repeated firmware uploads while refining a program, this is a real convenience.

To build their own system based on the adapter, a developer can use software from the example library or write their own software for the adapter.
Using the adapter in your own designs noticeably shortens development time and costs: there's no need to design and order a board or assembly (the cost of such an order would exceed the cost of the adapter, not to mention the time spent), no need to find or design a housing, and the adapter's universal software is suitable for solving many tasks.

Compared to adapters found on the Internet, the I2C SPI 1-Wire adapter USB differs in that it
  • works in MASTER mode (MASTER) - some of the adapters offered on the Internet cannot work in this mode;
  • connects directly to a computer's USB port (a USB-A connector);
  • the adapter board is designed to fit inexpensive commercially available housings and can be supplied by developers in a housing, as a finished device;
  • ready-made software examples are offered for specific devices;
  • drivers are available for different operating systems.
  • you can simultaneously connect to the adapter
    • several I2C-interface devices and up to three SPI-interface devices
      • or
    • several I2C-interface devices, up to two SPI-interface devices, and several 1-Wire-interface devices,
      • or
    • up to four SPI-interface devices and several 1-Wire-interface devices,
      • or
    • up to five SPI-interface devices.
The 7-bit address space of the I2C interface allows working with up to 128 connected devices;
the 64-bit address space of the 1-Wire interface theoretically allows working with 2^64 (two to the 64th power) devices.
In both cases, the number of devices will be limited more by the cable length and the current drawn by those devices.

Unused lines can be used as general-purpose inputs/outputs (general I/O).
The adapter provides 12 pins for connecting a cable.
8 of them are connected to signal lines:
3 lines - for the SPI interface,
1 - for device selection when working with SPI (each device connected to the adapter's SPI interface requires a separate select line for that device);
2 - for the I2C interface; if I2C is not used, 2 additional devices can be connected to the SPI interface instead;
1 - general-purpose input/output (I/O), can be used to connect one SPI device;
1 - for the 1-Wire interface; if 1-Wire is not used, one more SPI device can be connected.

What is the ability to connect several devices to different interfaces simultaneously good for?
Example system:
sensors are connected to the adapter - humidity, pressure and a clock real-time, via the I2C interface, several temperature sensors via the 1-Wire, an SD card via the SPI interface. With the appropriate program, such a device can record environmental parameters to the SD card for a long time, timestamped, without commands from a computer. If the interrupt line of the clock is connected to a general-purpose input/output, the microcontroller can be kept in sleep mode and woken up by an interrupt from that clockclock, and after reading the sensor values and writing them to the SD card, put the microcontroller back to sleep mode. Putting the microcontroller to sleep significantly reduces the average current drawn and extends the run time of an autonomous power source.
There is no particular point in reducing current consumption when powered over USB from a computer, but with the proposed configuration you can fully debug the microcontroller's program for standalone, power-saving operation.
The final version of the standalone device requires placing a battery and an SD card in a single housing together with the adapter.

Users can upload their own firmware to the microcontrollers of the I2C adapters SPI 1-Wire USB:

  • The I2C SPI 1-Wire USB adapter based on the STM8S003

                is reprogrammed by the user via a single-wire interface (SWIM). To program the microcontroller, STM8S003 an inexpensive programmer will work, for example, an ST-Link mini V2;

  • The I2C SPI 1-Wire USB adapter based on the ATmega8A, ATmega808

                is reprogrammed by the user via USB through a bootloader flashed into the microcontroller (bootloader) - a programmer is not needed for this.
               
If you need to upload your own firmware to the ATmega8A/ATmega328P I2C SPI 1-Wire adapter USB microcontroller, it is also possible via the SPI interface, using an inexpensive programmer, for example some AVR ISP for programming AVR microcontrollers. However, this requires first disconnecting any external devices connected to the SPI I2C SPI 1-Wire adapter USB interface (unsoldering the cable from the 6 pins I2C SPI 1-Wire adapter USB).  
With a full erase (Erase) of the microcontroller's program memory, which is normally performed before programming, the bootloader.
will also be erased. Further programming of the ATmega8A will then only be possible via the SPI interface, using a programmer, since the bootloader firmware is not provided separately. The same applies to the ATmega808, microcontroller as well, but it requires a programmer with a UPDI interface.
