Connecting Devices to the I2C SPI 1-Wire USB Adapter

Connecting 1-Wire-Interface Devices

Every slave device with the 1-Wire interface has a unique 64-bit address programmed in at the factory. For example, you can connect many DS18B20 temperature sensors to the 1-Wire interface - each of them is guaranteed to have an individual address. The interface provides a procedure for discovering the addresses of connected devices.
Note: for the 1-Wire interface, it's not always worth fully assembling a system with many identical devices, since their identification will be required - at which position, with which address, each device is located.
To identify a temperature sensor and its location, if possible, it's enough to change the temperature affecting the sensor while watching the readings of all the sensors.
For example, in a system, one of the DS18B20 temperature sensors can be squeezed in a hand - only that sensor's readings will change on the display device or in the logger.
If a system has several atmospheric pressure sensors, they can be placed in a sealed bag, and the bag squeezed.
But in some cases it can be difficult to identify an individual device in the system using such a method.
In that case it makes sense to build up the system by connecting one device at a time and identifying it. Devices can be connected one at a time in advance, their address determined, and each device labeled.


The pins for connecting devices with the 1-Wire interface are located on the underside of the adapter board, the side without any components.
For example, several DS18B20 temperature sensors can be connected to the adapter.
Their +U and GND pins are tied together - the sensors operate in parasite-power mode, drawing power from the data line DQ.
On the adapter board, parasite power is supplied to the IO1 line through a resistor with a resistance of 4.7k from the adapter's V power line.
Power can also be supplied to the sensors' +U pins from the adapter's V pin - for this, the sensors' +U and GND pins must be disconnected from each other



.

Connecting I2C-Interface Devices

In normal mode, the address of an I2C-interface device is defined by 7 bits, which allows addressing up to 128 devices.
A huge number of I2C-interface devices are manufactured, so devices with identical addresses can be encountered. Manufacturers often allow the device address to be changed by connecting its address-control line to power or to 0V - in that case, two identical devices can also be connected to the interface.
There is a sensor whose address-control line can be connected to the power rails, 0V, or to the interface lines SDA, SCL, which allows four identical sensors to be connected to the interface.



The pins for connecting devices with the I2C interface are located on the underside of the adapter board, the side without any components.
Pull-up resistors with a resistance of 10k are mounted on the adapter board - through them the adapter's supply voltage (the V line) is fed to the SDA line (labeled D on the adapter board) and SCL (labeled C).








Connecting SPI-Interface Devices

Hardware address support is not provided for SPI-interface devices. But each device usually has a select line (~CS). For a device to support SPI communication, the select line must first be set to a low logic level, and after the communication is finished, set back to a high level on that line.
If several devices are connected to the SPI interface, each of them must be controlled by its own separate select line.
Note: even if only one slave device is connected to the SPI master, and you weren't planning to run a select line, hoping to simply tie the device's ~CS pin to 0V, check the technical documentation to make sure toggling the ~CS line is not a mandatory condition for the device to operate.

Some devices come with two interfaces: the developer can choose between the I2C and SPI interfaces.
The I2C interface requires two signal lines: SDA and SCL.
The SPI interface uses four signal lines: MISO, MOSI, SCK, and ~CS, or three lines: in that variant, the MISO and MOSI signals are carried on a single line. Whether a device supports this mode can be found in its technical documentation.
Using the SPI interface lets you achieve a higher transfer speed than working over I2C.
For example, the technical datasheet for the ADXL345 accelerometer states that when connected via SPI the maximum sampling rate is 3200Hz;
if the ADXL345 is connected via the I2C, interface, then even at the maximum SCL clock frequency of 400kHz, the maximum sampling rate of the accelerometer is four times lower: 800Hz. This is explained by the transmission of the address, the transmission of other additional data, and the 400kHz clock-frequency limit for the I2C interface.



The pins for connecting devices with the SPI interface are located on the topside of the adapter board - the side where the components are mounted.
The pin names of an SPI slave device may differ;
SDI - input for data coming from the adapter (the master),
SDO - output for data from the slave device,
SCK - input for the clock signal sent by the adapter,
~CS - input for selecting the device;
if the adapter sets a high level on this input, the device does not respond to signals arriving over the SPI interface;
a low level on the ~CS pin, set by the adapter, puts the slave device's SPI interface into working mode.





Simultaneously Connecting Devices with Different Interfaces

It is possible to use all three interfaces simultaneously - connecting several I2C and 1-Wire devices and one or two SPI devices (the IO2 line can be used as a second ~CS line).
If some interfaces are not used, the unused lines can be used as general-purpose inputs/outputs (general I/O), or additional devices connected to the SPI interface of the adapter can be controlled over those lines.
In total, the adapter provides 12 pins for connecting a cable: two of them are connected to the V power line, and another two to the _|_ (Gnd) line;
8 of the pins are connected to signal lines:
3 lines - for the SPI interface (connected to pins C, I, O on the top side of the board),
1 line - for device selection when working with SPI (pin ~S on the top side of the board). Every device connected to the SPI interface requires a separate ~S.
1 line - general-purpose input/output (IO2); it can be used as the select line for an additional SPI device, or as a hardware interrupt input, for example letting you track the end of an accelerometer's conversion or wake the adapter's microcontroller from sleep mode when working with a real-time clock;
2 lines - for the I2C interface (pins C and D on the underside of the board); if I2C is not used, 2 additional devices can be connected to the SPI interface;
1 line - for the 1-Wire interface (pin IO1 on the underside of the board); if 1-Wire is not used, one more SPI device can be connected.

If, in the adapter with the ATmega8 microcontroller, the 1-Wire interface is not used, the IO1 pin can be used as a timer counting input.

The physical ability to connect many devices is limited by the total input capacitance of the connected devices and the cable capacitance - the longer the cable, the greater its capacitance. For example, the total capacitance of a single I2C interface line must not exceed 400pF.
Additional limits come from the drive capability of the microcontroller's outputs on the adapter board (up to 20mA) and the current the adapter's regulator can supply - up to 100mA for powering the adapter itself and any external devices connected to the adapter's V pin.
Connected devices can also be powered from a separate regulator; a mounting location for one is provided on the adapter board.
